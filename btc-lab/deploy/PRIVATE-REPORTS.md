# Private hourly reports

Run deploy/publish_report_macos.py --install using the existing release venv Python on the private Mac. Requires a fine-grained GitHub token with Contents read/write restricted to mrbinio/btc-lab-reports. Enter it at the hidden prompt, never in command arguments or chat. The script verifies the destination is private before every upload. It stores the token in ~/Library/Application Support/BTC Lab/reporting/token with mode 0600 inside a 0700 folder; it is not encrypted at rest. Re-run setup to replace an expired token.

A separate com.btc-lab.reports user launch agent publishes latest.json hourly while the user session and network are available. Mac sleep/offline time prevents delivery; freshness must be assessed from exported_at AND worker heartbeat, not GitHub commit time alone. Does not restart BTC Lab or alter port, authentication, database or risk. Database is opened read-only in a consistent transaction. Reports are allowlisted and exclude credentials, config, raw events and arbitrary error text. Financial amounts in accounts are dollars; trade integers use 1e6 scale. Latest 1000 trades have an explicit truncation flag; account totals include all positions. Decision counts are recorded throttled events, not opportunity counts. Raw books are not uploaded. History is retained by Git commits. GitHub token expiry or revoked access stops delivery; private reporting/status.json stores only sanitized status. Privacy verification is at request time, not protection against an owner subsequently making the repository public.

Install prints success only after initial upload and launch agent registration. Actual Mac installation and end-to-end upload are not verified by local tests. 46 local tests pass, including reporting allowlist/read-only snapshot, public destination refusal, update SHA and authorization failure. Assistant reads private files with GitHub fetch_file. User must finish setup; no live reporting is claimed before a Mac-produced report is read.
